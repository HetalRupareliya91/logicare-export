# Contributing

1. Create a branch from `main`: `feat/<area>-<topic>` or `fix/<area>-<topic>`.
2. Use conventional commits: `feat(backend): ...`, `fix(admin): ...`, `docs: ...`.
3. Keep pull requests focused on one module.
4. Every PR needs one approval from another team member before merge.
5. We use **rebase merge** to keep a linear history.

## Areas
- `backend` - REST API
- `frontend` - customer portal
- `admin` - admin panel
- `mobile` - Expo app
